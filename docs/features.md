# Mikoshi 功能规格（v1）

## 1. 定位

Mikoshi 是一个 Windows 桌面密码管理器，直接读写 KeePass 的 `.kdbx` 数据库。和 KeePassXC 相比，它的目标是：

- **界面更现代**
- **以快捷键为中心**：全局热键呼出快速搜索框、自动输入、应用内键盘操作
- **轻量**：只做日常用得到的功能

同一个 `.kdbx` 文件必须能在 Mikoshi、KeePass、KeePassXC、KeePassDX（Android）之间来回打开，数据不丢失。

## 2. 技术栈

| 层 | 选型 |
|---|---|
| 桌面框架 | Tauri 2（仅 Windows，WebView2） |
| 前端 | React + TypeScript + Vite，包管理用 pnpm |
| 后端 | Rust |
| KDBX 读写 | M0–M5 用 [`keepass`](https://github.com/sseemayer/keepass-rs) crate（MIT）0.17.x；M6 起换成自己写的无损读写层（`crates/kdbx`，2026-11-18 决定，原因见 milestones.md 的 M6） |
| 建议的 Tauri 插件 | global-shortcut、single-instance、autostart、dialog |

建议的应用标识：`com.elmtran.mikoshi`。

### keepass-rs 的已知限制（开发前必须先验证）

> 历史记录：M0 据此做了验证（见 m0-report.md），M6 起已不再使用 keepass-rs。

- 能读 KDB、KDBX 3.1 和 KDBX 4，但**写入标注为"实验性"，而且只能写 KDBX 4**
- 往返保存会不会丢数据**还没验证**。需要确认的有：无法识别的 XML 元素、CustomData（库、分组、条目三级）、历史记录、附件、标签、自定义图标、KDBX 4.1 新增的字段（如 `PreviousParentGroup`、`QualityCheck`）
- README 提到要按 CPU 设置编译参数才能有好的性能（见该仓库的 `.cargo/config.toml`）。debug 构建下 Argon2 会非常慢，需要给依赖单独开优化，例如 `[profile.dev.package."*"] opt-level = 3`

**第一项开发任务**是写一个往返测试脚手架（见 §7），先确认 keepass-rs 能不能用。如果会丢数据，再评估三条路：给上游提 PR、fork 后自己修，或者换方案。

## 3. v1 范围

v1 对应 KeePassXC 的功能模块 1–10。每个功能前的标记：**[必须]** 是 v1 一定要做的；**[可选]** 时间紧可以往后放。

### 3.1 打开与解锁

- [必须] 打开已有的 `.kdbx` 文件，解锁方式三种：只用主密码、只用密钥文件、主密码加密钥文件
- [必须] 密钥文件格式：XML（v1.0 和 v2.0）、32 字节二进制、64 位十六进制，其他任意文件取其哈希
- [必须] 支持读 KDBX 3.1、4.0 和 4.1
- [必须] 支持的密钥派生方式（KDF）：Argon2d、Argon2id、AES-KDF。支持的加密算法：AES-256、ChaCha20、Twofish
- [必须] 新建数据库：设主密码，可以再加一个密钥文件。加密参数用默认值（见 §3.8）
- [必须] 最近打开的文件列表，启动时自动选中上次用的库
- [必须] 解锁失败时说清楚原因：密码或密钥文件不对、文件损坏、格式不支持
- [可选] 记住每个库上次用的密钥文件路径（只存路径，不存内容）
- v1 同一时间只打开一个库，不做多库标签页

### 3.2 自动锁定

- [必须] 空闲超时锁定，时长可设置（默认 5 分钟），按全局的键盘鼠标空闲时间算
- [必须] Windows 锁屏时锁定
- [必须] 系统休眠或睡眠时锁定
- [必须] 快捷键手动锁定（见 §5）
- [可选] 窗口最小化时锁定（默认关）
- 锁定时释放内存里所有解密的数据，前端清空条目缓存；如果有没保存的修改，先按设置自动保存或提示

### 3.3 浏览

- [必须] 左侧分组树，中间条目列表，右侧条目详情，三栏布局
- [必须] 条目列表显示标题、用户名、URL 和修改时间，可以排序
- [必须] 详情里显示全部标准字段、自定义字段、标签、附件列表、创建/修改/过期时间
- [必须] 密码默认显示成掩码，点一下或按快捷键临时显示
- [必须] 过期的条目要有明显标记
- [必须] 显示 KeePass 的标准图标
- [可选] 显示自定义图标
- [必须] 回收站以普通分组的形式出现

### 3.4 搜索

- [必须] 在当前库里搜索，匹配标题、用户名、URL、备注和标签，不区分大小写，边输入边出结果
- [必须] 默认不搜回收站里的条目
- [可选] 简单的字段前缀语法：`title:`、`user:`、`url:`、`tag:`
- [可选] 模糊匹配和按匹配度排序。快速搜索框（§3.6）至少要有匹配度排序

### 3.5 复制与剪贴板

- [必须] 一键复制用户名、密码、URL，有 TOTP 的话也能复制 TOTP
- [必须] 复制密码、受保护字段或 TOTP 后，过一段时间自动清空剪贴板，时长可设置（默认 10 秒）；用户名、URL 等非秘密字段不定时清空。**只有剪贴板里还是我们放进去的内容时才清空**，不能误清用户之后自己复制的东西
- [必须] 复制密码或 TOTP 时，在剪贴板里同时写入以下格式，不让它进入 Win+V 历史和云剪贴板：
  - `ExcludeClipboardContentFromMonitorProcessing`
  - `CanIncludeInClipboardHistory` = DWORD 0
  - `CanUploadToCloudClipboard` = DWORD 0
- [必须] 应用退出或锁定时，如果剪贴板里还是我们复制的密码，立即清空
- [可选] 用默认浏览器打开 URL

### 3.6 托盘、全局热键与快速搜索框

- [必须] 托盘图标，菜单项：显示主窗口、锁定/解锁、快速搜索、退出
- [必须] 关闭主窗口时只隐藏到托盘，不退出
- [必须] 单实例：再次启动程序时把已有的窗口切到前台
- [可选] 开机自启（默认关）
- [必须] **快速搜索框**：
  - 按全局热键呼出，无边框，居中，置顶，不在任务栏显示
  - 库还没解锁时，先显示主密码输入框，解锁后进入搜索
  - 边输入边出结果，方向键选择
  - `Enter`：隐藏，再对**呼出前的那个窗口**执行自动输入（§3.10），用条目自己的序列（默认 `{USERNAME}{TAB}{PASSWORD}{ENTER}`）
  - `Ctrl+Enter`：隐藏，再对呼出前的那个窗口只输入密码（不加 Tab 和回车）
  - 复制：在结果上右键，菜单里有复制用户名、复制密码、复制 TOTP；快捷键 `Ctrl+C` 复制密码，`Ctrl+B` 复制用户名，`Ctrl+T` 复制 TOTP
  - （2026-11-18 调整：原来是 `Enter` 复制密码、`Ctrl+Enter` 自动输入。M4 仍按原来的做，M5 改成上面这样）
  - `Esc` 或窗口失去焦点时隐藏
- [必须] 所有全局热键都能在设置里修改。注册失败（被别的程序占用）时要提示用户

### 3.7 TOTP

- [必须] 读取条目的 `otp` 字段（`otpauth://` URI），显示当前验证码和剩余秒数倒计时
- [必须] 复制 TOTP 的入口（§3.5、§5）
- [可选] 兼容 KeePass 2 原生的 TOTP 存法：`TimeOtp-Secret-Base32` 等字段
- [必须] 编辑条目时可以设置 TOTP：粘贴 `otpauth://` URI，或者手动填密钥

### 3.8 编辑

- [必须] 新增、编辑、删除条目。标准字段有标题、用户名、密码、URL、备注、标签、过期时间
- [必须] 自定义字段：增删改，每个字段可以单独标为受保护
- [必须] 编辑条目前自动把旧版本存进历史记录；历史条数上限沿用库里的设置
- [必须] 查看历史版本，并且能恢复到某个版本
- [必须] 删除时移到回收站；在回收站里再删就是永久删除，要二次确认；可以清空回收站
- [必须] 分组：新增、重命名、删除（进回收站）、移动
- [必须] 条目在分组之间移动，用拖拽或菜单都行
- [必须] 附件：查看列表、导出到文件
- [可选] 附件：添加、删除
- [可选] 从 KeePass 标准图标里选图标。自定义图标不做编辑，但必须原样保留
- [必须] **保存**：
  - 先写临时文件，再原子替换原文件
  - 每次保存前保留一份上一版的备份（`*.kdbx.bak`，可以关）
  - 保存前检查文件有没有被外部改过（对比打开时记下的修改时间和哈希）。被改过就提示用户：重新加载（放弃本地修改）、强制覆盖，或取消。v1 不做合并
  - 沿用原来的加密算法、KDF 参数和压缩设置
  - Mikoshi 只写 KDBX 4.1，所以 KDBX 3.1 和 4.0 的库第一次保存后都会变成 4.1。保存前提示用户，并说明 KeePass 2.48 以上能完整支持；KeePassXC 2.8 已实测能打开（2026-11-18 确认）
  - 新建库的默认参数：KDBX 4，AES-256 或 ChaCha20，Argon2id。KDF 参数要让解锁大约花 1 秒
- [必须] 标题栏显示是否有未保存的修改，`Ctrl+S` 保存
- [可选] 每次修改后自动保存（默认关）

### 3.9 密码生成器

- [必须] 随机字符模式：长度、大写、小写、数字、符号都能设置，可以排除容易混淆的字符（`0O1lI|` 等）
- [必须] 用系统的安全随机数（CSPRNG）生成
- [必须] 显示强度估算（例如用 zxcvbn）
- [必须] 编辑条目时可以直接调出生成器填进密码栏；也能单独打开生成器，只复制结果
- [可选] 口令短语模式（例如 EFF 词表，需要把词表打包进程序）
- 记住上次用的生成参数

### 3.10 自动输入（Auto-Type）

- [必须] 全局热键触发：读取当前前台窗口的标题，匹配条目，把序列模拟成键盘输入
- [必须] 匹配规则：
  - 条目的窗口关联（Window Associations），支持 `*` 通配符
  - 没有窗口关联的条目，看窗口标题里是否包含条目标题
  - 浏览器网址（2026-11-18 加入）：前台是 Edge、Chrome、Brave、Vivaldi、Firefox 时，读地址栏里的网址，和条目的 URL 比较主机名：相同，或者是条目主机名的子域名（`accounts.example.com` 匹配 `example.com`）就算匹配。条目 URL 开头的 `www.` 忽略
  - [可选] 正则规则 `//…//`
- [必须] 匹配到多个条目时弹出选择框；一个都没匹配到时，打开快速搜索框让用户自己选
- [必须] 默认序列 `{USERNAME}{TAB}{PASSWORD}{ENTER}`；条目和窗口关联可以自定义序列
- [必须] 条目编辑器里可以改自动输入设置（2026-11-20 加入，F5）：开关、条目自己的序列（留空继承分组或默认序列，并显示实际会用哪个）、窗口规则（窗口标题 `*` 通配符或 `//正则//`，可单独指定序列）；常用占位符一点就插入；序列认不出时即时提示，保存时也拒绝
- [必须] 支持的占位符：`{USERNAME}` `{PASSWORD}` `{URL}` `{TITLE}` `{NOTES}` `{TOTP}` `{S:字段名}` `{TAB}` `{ENTER}` `{SPACE}` `{BACKSPACE}` `{DELAY n}` `{DELAY=n}`，以及转义字符 `{+}` `{%}` `{^}` `{~}` `{(}` `{)}` `{{}` `{}}`
- [必须] 和 KeePass 2、KeePassXC 兼容的其他占位符（2026-11-20 加入，F3）：
  - `{CLEARFIELD}`：清空当前输入框，按 KeePassXC 的做法依次按 `Ctrl+Home`、`Ctrl+Shift+End`、`Backspace`
  - 值：`{TIMEOTP}`（同 `{TOTP}`）、`{GROUP}`、`{GROUP_PATH}`（不含根分组，用 `.` 连接）、`{UUID}`、`{URL:RMVSCM}`/`{URL:WITHOUTSCHEME}` `{URL:SCM}` `{URL:HOST}` `{URL:PORT}` `{URL:PATH}` `{URL:QUERY}` `{URL:FRAGMENT}` `{URL:USERINFO}` `{URL:USERNAME}` `{URL:PASSWORD}`、`{DT_SIMPLE}` `{DT_YEAR}` `{DT_MONTH}` `{DT_DAY}` `{DT_HOUR}` `{DT_MINUTE}` `{DT_SECOND}` 及 `{DT_UTC_…}`
  - 按键：`{DELETE}`/`{DEL}` `{INSERT}`/`{INS}` `{HOME}` `{END}` `{PGUP}` `{PGDN}` 方向键 `{ESC}` `{F1}`–`{F24}` `{WIN}`/`{LWIN}` `{RWIN}` `{APPS}` `{CAPSLOCK}` `{NUMLOCK}` `{SCROLLLOCK}` `{PRTSC}` `{BREAK}` `{HELP}` `{ADD}` `{SUBTRACT}` `{MULTIPLY}` `{DIVIDE}` `{NUMPAD0}`–`{NUMPAD9}` `{VKEY n}` `{VKEY-EX n}` `{VKEY-NX n}`，按键后可跟次数（`{TAB 2}`）
  - 转义名称：`{PLUS}` `{PERCENT}` `{CARET}` `{TILDE}` `{LEFTPAREN}` `{RIGHTPAREN}` `{LEFTBRACE}` `{RIGHTBRACE}`，以及 `{[}` `{]}`
  - 其他：`{BEEP 频率 毫秒}`、KeePassXC 的 `{MODE=VIRTUAL}`（之后的字符按当前键盘布局的按键输入，给远程桌面、游戏这类不认 Unicode 输入的程序）、`{C:注释}`（什么都不输入）
  - 不支持：需要弹窗或交互的（`{PICKCHARS}` `{PICKFIELD}` `{NEWPASSWORD}`）、会运行程序或改库的（`{CMD:…}` `{HMACOTP}` `{APPACTIVATE …}`）、文本变换（`{T-REPLACE-RX:…}` `{T-CONV:…}`）、字段引用 `{REF:…}`、环境变量和库路径（`%变量%` `{DB_…}` `{ENV_…}`）。遇到这些仍然整段不输入，并在日志里记下是哪个占位符
- [可选] 修饰键前缀 `+`（Shift）、`^`（Ctrl）、`%`（Alt）
- 实现要点：
  - 用 `SendInput`。普通字符用 `KEYEVENTF_UNICODE`，Tab、Enter 等功能键用虚拟键码
  - 开始输入前，等用户松开触发热键时按着的修饰键
  - 按键间隔可设置
  - 输入前确认前台窗口没变；变了就中止
  - **中文输入法**：输入前先处理输入法状态（切到英文模式或关闭输入法），输入完再恢复。具体做法开发时要实测：微软拼音、搜狗
  - **UIPI**：目标窗口以管理员身份运行时，普通权限进程发出的按键会被系统拦截。要检测这种情况并提示用户，而不是什么都不输入、也不报错

### 3.11 界面

M1 确定（2026-11-17）：

- [必须] Windows 11 原生风格，加一条渐变强调色和少量交互动效；系统开了"减少动画"时关闭动效
- [必须] 深色模式：跟随系统、浅色、深色三个选项
- [必须] 界面语言：中文和英文，默认跟随系统（系统是中文用中文，其他语言用英文）

### 3.12 快速保存

2026-11-21 加入（内测时补上）：

- [必须] 全局热键（默认 `Ctrl+Alt+N`）把快速搜索框打开成一个新建条目的小表单：标题、网址、用户名、密码、分组。再按一次关闭；按快速搜索热键切回搜索
- [必须] 预填：前台是浏览器（和自动输入同一份名单，同样从地址栏读网址）时，网址填网站（`https://主机名[:端口]`，路径、查询串、片段都不要：里面可能有会话令牌，条目本来也按主机名匹配），标题填去掉 `www.` 的主机名；其他程序填窗口标题，网址留空；地址栏里不是网页（`chrome://`、正在输入的搜索词）时按其他程序处理
  - 地址栏不显示 `http://` 和 `https://`：`localhost` 和 IP 地址（本机开发服务器、路由器）按 `http`，其他按 `https`；地址栏里写明了的照写（2026-11-21 内测）
  - 中文域名填中文写法，不填 `xn--…`；自动输入比较主机名时两种写法算同一个（2026-11-21 内测）
- [必须] 用户名（2026-11-21 内测加入）：按热键时光标所在的是普通单行输入框，就把里面的字带进来；不是的话，找页面上第一个密码框前面那个输入框。密码带不过来：浏览器和 Windows 对外只给圆点，也不让复制，只有浏览器扩展才拿得到。带进了用户名时光标直接停在密码框
- [必须] 密码旁边有生成器（`Ctrl+G` 开关），展开在表单里，"使用这个密码"填进密码框并显示出来；有强度条
- [必须] 分组默认上次快速保存用的分组（记在设置里，只存 uuid），当前库没有这个分组就用根分组；不能选回收站
- [必须] 这个网站已经有条目时，在表单里提示是哪几个，免得重复保存
- [必须] `Enter` 保存；`Ctrl+Enter` 保存后关闭表单，把密码输入回原来的窗口（注册页面用），和快速搜索框的"只输入密码"一样
- [必须] 开着"每次修改后保存"时立刻写入文件；写不进去（文件被别处改过、要升级格式、磁盘错误）时条目留在库里，提示到主窗口处理；关着时和其他修改一样等用户保存
- [必须] 库锁着时先在框里解锁，解锁后接着显示表单
- 快速搜索框的权限只多了"新建条目"和生成器：仍然不能浏览分组、看已有条目的值、改已有条目

## 5. 快捷键（默认值，全部可改）

### 全局

| 操作 | 默认 | 说明 |
|---|---|---|
| 呼出快速搜索框 | `Ctrl+Alt+K` | |

## 6. 安全要求

- **明文只留在 Rust 端**：前端只拿条目的元数据（标题、用户名、URL 等）。密码、受保护字段和 TOTP 密钥默认不发给前端；复制、自动输入、生成 TOTP 都在 Rust 端用条目 ID 完成。只有用户主动点"显示密码"或进入编辑时，才把这一个条目的值发给前端，用完就清掉
- Rust 端敏感数据尽量用 `zeroize` 或 `SecStr` 这类能擦除的类型，锁定时释放
- 日志、错误信息、崩溃报告里不能出现密码、受保护字段或主密码
- 配置文件（`%APPDATA%\com.elmtran.mikoshi\`）只存非敏感信息：最近文件路径、密钥文件路径、界面设置、热键
- Release 构建关闭 DevTools，配置严格的 CSP，不加载任何远程资源
- v1 没有任何联网功能
- 单实例运行

## 7. 测试与验收

### 往返测试（最重要）

- 用 KeePassXC 和 KeePass 2 生成一组测试库，放在 `tests/fixtures/`。**只能是测试数据**，至少覆盖：
  - KDBX 3.1 和 KDBX 4.x
  - KDF：Argon2d、Argon2id、AES-KDF；加密算法：AES、ChaCha20、Twofish
  - 只用密码、只用密钥文件（几种格式）、密码加密钥文件
  - 历史记录、附件、自定义字段、受保护字段、标签、过期时间、自定义图标、CustomData、回收站、TOTP、自动输入的窗口关联
- 自动化测试：打开 → 保存 → 重新打开，把两次的内容（或导出的 XML）逐项比对，不能有任何字段丢失
- 每个版本发布前做一次人工验证：用 Mikoshi 改过并保存的库，在 KeePassXC 里打开，抽查内容

### 功能验收

- §3 里每条 [必须] 都要能实际操作通过
- 自动输入至少在这些地方实测过：浏览器登录页（Edge、Chrome）、记事本、开着中文输入法的场景、以管理员身份运行的窗口（要能看到提示）
- 剪贴板：复制密码后 Win+V 历史里看不到；到时间自动清空；清空前用户自己又复制了别的内容时，不会被误清
